Project 4A: Image Warping and Mosaicing

In this project, I register overlapping photographs with projective transformations (homographies), warp them into a common frame with my own inverse-warping code, and blend them into image mosaics. The pipeline is: pick point correspondences by hand, solve for homographies by least squares, inverse-warp with nearest neighbour and bilinear interpolation, blend with weighted averaging (plain feathering and a 2-level Laplacian pyramid), and finally re-project the photos onto a cylinder (A.5).

Implementation notes:

Points are (x, y) = (column, row), and pixel (0, 0) is the center of the top-left pixel. A homography maps points of image 1 to image 2: \(p' = Hp\). All photos are downscaled so that the longest side is 1000 px before processing.

I shot three sets of photos, each with three overlapping views. Within a set, I rotated the camera about a fixed position between shots, so the views are related by a projective transformation (a homography), and neighbouring photos overlap substantially. Each set is shown from left to right.

A.2: Recover Homographies

Method

A homography is a 3x3 matrix \(H\) with 8 degrees of freedom (the bottom-right entry is fixed to 1) such that \(p' \simeq Hp\) in homogeneous coordinates. For one correspondence \((x, y) \rightarrow (x', y')\): $$ x' = \frac{h_{11}x + h_{12}y + h_{13}}{h_{31}x + h_{32}y + 1}, \qquad y' = \frac{h_{21}x + h_{22}y + h_{23}}{h_{31}x + h_{32}y + 1} $$ Multiplying out the denominator makes both equations linear in the eight unknowns: $$ h_{11}x + h_{12}y + h_{13} - h_{31}xx' - h_{32}yx' = x' $$ $$ h_{21}x + h_{22}y + h_{23} - h_{31}xy' - h_{32}yy' = y' $$ So each correspondence contributes two rows to the system \(A\mathbf{h} = \mathbf{b}\), where \(\mathbf{h} = [h_{11}, h_{12}, h_{13}, h_{21}, h_{22}, h_{23}, h_{31}, h_{32}]^T\): $$ \begin{bmatrix} x & y & 1 & 0 & 0 & 0 & -xx' & -yx' \\ 0 & 0 & 0 & x & y & 1 & -xy' & -yy' \end{bmatrix} \mathbf{h} = \begin{bmatrix} x' \\ y' \end{bmatrix} $$ Four correspondences give a square system, but a couple of pixels of click error then change \(H\) a lot. Therefore, I click 8 correspondences per image pair (16 equations for 8 unknowns) and solve the overdetermined system in the least-squares sense with numpy.linalg.lstsq. I picked the points manually using a matplotlib ginput window that shows both images side by side, choosing distinctive, static features (corners of windows, roofs and buildings) that are far from the camera, so that parallax is small. 

def build_system(im1_pts, im2_pts):
    p = np.asarray(im1_pts, dtype=np.float64)
    q = np.asarray(im2_pts, dtype=np.float64)
    if p.shape != q.shape or p.ndim != 2 or p.shape[1] != 2:
        raise ValueError("im1_pts and im2_pts must both be n-by-2")
    n = len(p)
    if n < 4:
        raise ValueError("need at least 4 correspondences")
    x, y = p[:, 0], p[:, 1]
    xp, yp = q[:, 0], q[:, 1]
    A = np.zeros((2 * n, 8))
    b = np.zeros(2 * n)
    A[0::2, 0], A[0::2, 1], A[0::2, 2] = x, y, 1
    A[0::2, 6], A[0::2, 7] = -x * xp, -y * xp
    b[0::2] = xp
    A[1::2, 3], A[1::2, 4], A[1::2, 5] = x, y, 1
    A[1::2, 6], A[1::2, 7] = -x * yp, -y * yp
    b[1::2] = yp
    return A, b

def computeH(im1_pts, im2_pts):
    A, b = build_system(im1_pts, im2_pts)
    h, *_ = np.linalg.lstsq(A, b, rcond=None)
    return np.append(h, 1.0).reshape(3, 3)

A.3: Warp the Images

Inverse Warping

To warp an image by \(H\), I work backwards from the output so that there are no holes:

  1. Push the four corners of the input image through \(H\) (and divide by the homogeneous coordinate) to get the bounding box of the result. This fixes the output size and an offset, since the warped image can have negative coordinates.
  2. For every output pixel \((u, v)\), compute its location in the destination plane (the pixel plus the offset) and map it back with \(H^{-1}\), then divide by the third coordinate to get a floating-point source location \((x, y)\).
  3. Sample the source at \((x, y)\) with one of two interpolation schemes. Output pixels whose source location falls outside the input get alpha = 0. Colors are interpolated premultiplied by alpha, so edges do not bleed into the empty region, and the alpha channel is later used for blending.

Nearest neighbour rounds \((x, y)\) to the closest pixel and copies it. Bilinear takes the four surrounding pixels and weights them by the fractional offsets. With \(x_0 = \lfloor x \rfloor\), \(y_0 = \lfloor y \rfloor\), \(f_x = x - x_0\) and \(f_y = y - y_0\): $$ I(x, y) = (1-f_x)(1-f_y)I(x_0, y_0) + f_x(1-f_y)I(x_0+1, y_0) + (1-f_x)f_yI(x_0, y_0+1) + f_xf_yI(x_0+1, y_0+1) $$ Both are written from scratch and vectorized with NumPy (processed in row chunks to bound memory). 

def _sample(im, sx, sy, interp):
    h, w, C = im.shape
    inside = (sx >= 0) & (sx <= w - 1) & (sy >= 0) & (sy <= h - 1)
    vals = np.zeros((sx.size, C))
    x, y = sx[inside], sy[inside]
    if interp == "nearest":
        xi = np.rint(x).astype(int)
        yi = np.rint(y).astype(int)
        vals[inside] = im[yi, xi]
    elif interp == "bilinear":
        x0 = np.clip(np.floor(x).astype(int), 0, max(w - 2, 0))
        y0 = np.clip(np.floor(y).astype(int), 0, max(h - 2, 0))
        x1 = np.minimum(x0 + 1, w - 1)
        y1 = np.minimum(y0 + 1, h - 1)
        fx = (x - x0)[:, None]
        fy = (y - y0)[:, None]
        vals[inside] = (im[y0, x0] * (1 - fx) * (1 - fy) + im[y0, x1] * fx * (1 - fy) +
                        im[y1, x0] * (1 - fx) * fy + im[y1, x1] * fx * fy)
    else:
        raise ValueError(interp)
    return vals, inside

def _warp(im, H, interp, out_shape=None, offset=None):
    C = im.shape[2]
    if out_shape is None or offset is None:
        x0, y0, x1, y1 = _bbox(im.shape, H)
        offset = (x0, y0)
        out_shape = (y1 - y0 + 1, x1 - x0 + 1)
    oh, ow = out_shape
    Hinv = np.linalg.inv(H)
    out = np.zeros((oh, ow, C))
    xs = np.arange(ow) + offset[0]
    rows = max(1, 1_500_000 // ow)
    for r0 in range(0, oh, rows):
        r1 = min(oh, r0 + rows)
        ys = np.arange(r0, r1) + offset[1]
        X, Y = np.meshgrid(xs, ys)
        pts = np.stack([X.ravel(), Y.ravel(), np.ones(X.size)])
        s = Hinv @ pts
        z = s[2]
        z = np.where(np.abs(z) > 1e-12, z, np.nan)
        with np.errstate(invalid="ignore"):
            sx, sy = s[0] / z, s[1] / z
        vals, _ = _sample(im, sx, sy, interp)
        out[r0:r1] = vals.reshape(r1 - r0, ow, C)
    return out, tuple(offset)

def warpImageNearestNeighbour(im, H, out_shape=None, offset=None):
    out, off = _warp(_premult(im), H, "nearest", out_shape, offset)
    return _unpremult(out), off

def warpImageBilinear(im, H, out_shape=None, offset=None):
    out, off = _warp(_premult(im), H, "bilinear", out_shape, offset)
    return _unpremult(out), off

Nearest Neighbour vs. Bilinear

Quality. Nearest neighbour copies one source pixel to each output pixel, so straight edges that are not axis-aligned come out as staircases, thin lines can break up or change thickness, and fine texture can shimmer. Bilinear averages four neighbours, so edges are smooth and continuous, at the price of slight blurring since it acts as a small low-pass filter. The difference images above (|NN - Bilinear| x 5) are concentrated along edges and high-contrast detail, such as the outlines of the numeral and letters, while flat regions agree. Neither method handles strong minification well, since both sample the source without pre-filtering, so heavily shrunk regions can alias.

Speed. Nearest neighbour needs one memory lookup per output pixel and channel. Bilinear needs four lookups plus a handful of multiplies and adds, so it does more work per pixel. The measured runtimes of the two functions on the rectified images (from the script's timer) are:

For the mosaics, I always use bilinear, since the extra cost is small compared with the quality gain, and a visible seam would be far worse than slight blur.

A.4: Blend the Images into a Mosaic

Procedure

  1. Register. For each pair of neighbouring photos, I solve for \(H\) as in A.2. The middle photo is the reference (it stays unwarped), and the others are chained into its frame: the left image uses \(H_{1 \to 2}\), and the right image uses the inverse of \(H_{2 \to 3}\).
  2. Canvas. I transform the corners of every image into the reference frame, take the union bounding box, and allocate one canvas for the whole mosaic (the one-shot approach).
  3. Warp. Each image is inverse-warped (bilinear) onto the canvas, giving for each image a color layer, an alpha mask (where the image has data), and a weight map.
  4. Weights. In each source image, the weight at a pixel is its distance to the nearest image border (Euclidean distance transform, normalized to a maximum of 1), which is a linear falloff from 1 at the center to 0 at the edges. The weight map is warped together with the image, so the weights stay consistent with the geometry.
  5. Blend. I implemented two options:
    • Feathering: the per-pixel weighted average \( \sum_i w_i c_i / \sum_i w_i \).
    • Two-band (2-level Laplacian) blending: each image is split into a low-pass layer (Gaussian blur with \(\sigma = 5\) px, normalized by the alpha mask so that empty pixels do not darken the edges) and a high-pass residual (image minus low-pass). The low-pass layers are feathered with the weights above, which gives a smooth transition in color and exposure. For the high-pass layer, I take at each pixel the value from the single image with the largest weight, which avoids ghosting of fine detail where the registration is off by a pixel or two.
def weight_map(alpha):
    m = np.pad(alpha > 0.5, 1)
    d = ndimage.distance_transform_edt(m)[1:-1, 1:-1]
    return d / (d.max() + 1e-9)

def blend_images(colors, alphas, weights, mode="twoband", sigma=5.0):
    W = np.stack(weights)
    Wsum = W.sum(axis=0)
    denom = np.maximum(Wsum, 1e-9)[..., None]
    if mode == "feather":
        out = sum(w[..., None] * c for w, c in zip(weights, colors)) / denom
    elif mode == "twoband":
        lows, highs = [], []
        for c, a in zip(colors, alphas):
            m = (a > 0.5).astype(float)
            # normalized blur: don't let empty (black) pixels leak into the low band
            low = ndimage.gaussian_filter(c * m[..., None], sigma=(sigma, sigma, 0))
            low /= ndimage.gaussian_filter(m, sigma)[..., None] + 1e-9
            lows.append(low * m[..., None])
            highs.append((c - low) * m[..., None])
        low_out = sum(w[..., None] * l for w, l in zip(weights, lows)) / denom
        idx = np.argmax(W, axis=0)[None, ..., None]
        high_out = np.take_along_axis(np.stack(highs), idx, axis=0)[0]
        out = low_out + high_out
    else:
        raise ValueError("blend must be 'feather' or 'twoband'")
    out = np.clip(out, 0, 1)
    out[Wsum <= 1e-9] = 0
    alpha = (Wsum > 1e-9).astype(float)
    return np.dstack([out, alpha])

def build_mosaic(images, Hs, blend="twoband", sigma=5.0, max_pixels=60e6):
    boxes = [_bbox(im.shape, H) for im, H in zip(images, Hs)]
    x0 = min(b[0] for b in boxes); y0 = min(b[1] for b in boxes)
    x1 = max(b[2] for b in boxes); y1 = max(b[3] for b in boxes)
    out_shape = (y1 - y0 + 1, x1 - x0 + 1)
    if out_shape[0] * out_shape[1] > max_pixels:
        raise ValueError("Mosaic canvas would be %dx%d. Something is badly off with "
                         "the homographies (bad correspondences?)." % out_shape[::-1])
    colors, alphas, weights = [], [], []
    for im, H in zip(images, Hs):
        a = im[..., 3] if im.shape[2] == 4 else np.ones(im.shape[:2])
        stack = np.dstack([im[..., :3] * a[..., None], a, weight_map(a)])
        out, _ = _warp(stack, H, "bilinear", out_shape, (x0, y0))
        al = out[..., 3]
        keep = al > 0.5
        col = out[..., :3] / np.maximum(al, 1e-6)[..., None]
        colors.append(np.clip(col, 0, 1) * keep[..., None])
        alphas.append(al * keep)
        weights.append(out[..., 4] * keep)
    return blend_images(colors, alphas, weights, blend, sigma), (x0, y0)

def homographies_to_reference(pair_pts, n, ref, model="homography"):
    est = computeH if model == "homography" else computeTranslation
    fwd = [est(a, b) for a, b in pair_pts]          # i -> i+1
    Hs = [None] * n
    Hs[ref] = np.eye(3)
    for i in range(ref - 1, -1, -1):
        Hs[i] = Hs[i + 1] @ fwd[i]
    for i in range(ref + 1, n):
        Hs[i] = Hs[i - 1] @ np.linalg.inv(fwd[i - 1])
    return [H / H[2, 2] for H in Hs]

A.5: Bells & Whistles: Cylindrical Projection

A planar mosaic maps everything onto one image plane, so images far from the reference get stretched. For example, in set 2 the homography for image 1 to image 2 has \(h_{11} = 1.84\) and \(h_{22} = 1.63\). A cylinder is a better model for a camera that pans. I project every photo onto a cylinder of radius \(f\) (the focal length in pixels), after which a pure camera rotation about the vertical axis becomes a horizontal translation between neighbouring images. Stitching then needs only a translation instead of a full homography.

Inverse Sampling from the Original Photos

For each pixel \((u, v)\) of the cylindrical image (measured from the image center), with \(\theta = u / f\): $$ x_{src} = f\tan\theta + c_x, \qquad y_{src} = \frac{v}{\cos\theta} + c_y $$ Every output pixel is sampled (bilinearly) directly from the original photo with no intermediate resampling, which keeps the full original resolution. I also implemented the forward mapping $$ (x, y) \rightarrow \left( f\arctan\frac{x - c_x}{f},\; \frac{f\,(y - c_y)}{\sqrt{(x - c_x)^2 + f^2}} \right) $$ so that correspondences can be clicked on the original photos and then projected onto the cylinder.

Choosing the Focal Length Automatically

The translation for each pair is then the mean displacement of its projected points. The images are chained to the middle image and blended with the same two-band code as in A.4.

def cylinder_forward(pts, shape, f):
    h, w = shape[:2]
    cx, cy = (w - 1) / 2.0, (h - 1) / 2.0
    p = np.asarray(pts, float)
    dx = p[:, 0] - cx
    u = f * np.arctan(dx / f)
    v = f * (p[:, 1] - cy) / np.hypot(dx, f)
    return np.c_[u + (_cyl_width(shape, f) - 1) / 2.0, v + cy]

def estimate_cyl_ratio(pair_pts, shapes, lo=0.4, hi=1.8):
    rs = np.linspace(lo, hi, 281)
    c = [_cyl_residual(pair_pts, shapes, r) for r in rs]
    k = int(np.argmin(c))
    rs2 = np.linspace(rs[max(k - 1, 0)], rs[min(k + 1, len(rs) - 1)], 101)
    c2 = [_cyl_residual(pair_pts, shapes, r) for r in rs2]
    j = int(np.argmin(c2))
    return float(rs2[j]), float(c2[j])

def cylindricalWarp(im, f):
    im4 = _premult(im)
    h, w, _ = im4.shape
    cx, cy = (w - 1) / 2.0, (h - 1) / 2.0
    ow = _cyl_width(im4.shape, f)
    u = np.arange(ow) - (ow - 1) / 2.0
    v = np.arange(h) - cy
    U, V = np.meshgrid(u, v)
    th = U / f
    sx = f * np.tan(th) + cx
    sy = V / np.cos(th) + cy
    vals, _ = _sample(im4, sx.ravel(), sy.ravel(), "bilinear")
    return _unpremult(vals.reshape(h, ow, -1))

B.1: Harris Corner Detection and ANMS

Harris corners

I convert the image to grayscale and compute the gradients \(I_x, I_y\) with derivative-of-Gaussian filters at \(\sigma_d = 1\). The products \(I_x^2\), \(I_y^2\), \(I_xI_y\) are smoothed with a Gaussian at \(\sigma_i = 1.5\sigma_d\) to form the structure tensor \(S = \begin{bmatrix} S_{xx} & S_{xy} \\ S_{xy} & S_{yy} \end{bmatrix}\), and the corner strength is the harmonic mean of its eigenvalues, $$ f_{HM} = \frac{\det S}{\operatorname{tr} S} = \frac{\lambda_1\lambda_2}{\lambda_1 + \lambda_2}, $$ which is large only when both eigenvalues are large (a corner, not an edge). A pixel is a corner candidate if it is a 3×3 local maximum of \(f_{HM}\) and its response is at least 1% of the strongest response in the image. As the assignment says, I use a single scale and no sub-pixel refinement. Candidates within 20 px of the border are discarded so that the 40×40 descriptor window always fits inside the image.

Adaptive Non-Maximal Suppression

Simply keeping the strongest 500 corners tends to cluster them in a few high-contrast regions and leaves other regions (which may contain the overlap between two photos) without any features. ANMS instead keeps corners that are strong and spread out. For each corner \(\mathbf{x}_i\) I compute its suppression radius, the distance to the nearest corner that is significantly stronger: $$ r_i = \min_{j}\; \lVert \mathbf{x}_i - \mathbf{x}_j \rVert \quad \text{s.t.} \quad f(\mathbf{x}_i) < c_{robust}\, f(\mathbf{x}_j), \qquad c_{robust} = 0.9 $$ and keep the 500 corners with the largest radii. The strongest corner in the image has no stronger neighbour, so its radius is infinite and it is always kept. Implementation: I sort the corners by strength, so that only the corners before \(i\) in the list can dominate corner \(i\), and compute each radius with one vectorized NumPy distance computation (the candidate list is capped at 10,000 corners, and the images here had 2,295 to 5,777). 

def harris_corners(gray, edge_discard=20):
    h, coords = get_harris_corners(gray, edge_discard)
    ys, xs = coords
    strengths = h[ys, xs]
    keep = strengths > HARRIS_THRESH_REL * h.max()
    ys, xs, strengths = ys[keep], xs[keep], strengths[keep]
    order = np.argsort(-strengths)[:MAX_CANDIDATES]

    return h, np.c_[xs, ys][order].astype(float), strengths[order]


def anms(pts, strengths, n_keep, c_robust=C_ROBUST, chunk=500):
    order = np.argsort(-strengths)
    pts, s = pts[order], strengths[order]
    n = len(s)
    radii = np.full(n, np.inf)

    for i0 in range(0, n, chunk):
        i1 = min(n, i0 + chunk)
        D2 = dist2(pts[i0:i1], pts[:i1])
        dominated = c_robust * s[None, :i1] > s[i0:i1, None]
        radii[i0:i1] = np.where(dominated, D2, np.inf).min(axis=1)
    keep = np.argsort(-radii, kind="stable")[:n_keep]

    return pts[keep], s[keep]

B.2: Feature Descriptor Extraction

For every ANMS corner I build a descriptor in three steps:

  1. Blur. The grayscale image is blurred with a Gaussian (\(\sigma = 2.5\) px).
  2. Sample. From the 40×40 window centered on the corner, I take an 8×8 grid of samples with a spacing of 5 px (offsets \(-17.5, -12.5, \dots, +17.5\) in each direction, read with bilinear interpolation). Sampling a coarse grid from a blurred window, rather than shrinking an 8×8 crop, gives a large, smooth descriptor that tolerates small localization errors and the mild perspective change between the photos, and the blur prevents aliasing when subsampling by a factor of 5.
  3. Bias/gain normalize. Each 64-vector \(p\) is replaced by \(d = (p - \mu)/\sigma\), where \(\mu\) and \(\sigma\) are its mean and standard deviation. This makes the descriptor invariant to affine changes in intensity \(I' = aI + b\), such as exposure differences between shots.

These descriptors are axis-aligned (no rotation invariance in the base pipeline; see B.5), and, as instructed, I skip the wavelet transform part of the descriptor section of the paper. 

def extract_descriptors(gray, pts, rotation_invariant=False):
    blurred = ndimage.gaussian_filter(gray, DESC_BLUR_SIGMA)
    spacing = WINDOW / PATCH
    offs = (np.arange(PATCH) - (PATCH - 1) / 2.0) * spacing
    U, V = np.meshgrid(offs, offs)

    if rotation_invariant:
        gx = ndimage.gaussian_filter(gray, ORIENT_SIGMA, order=(0, 1))
        gy = ndimage.gaussian_filter(gray, ORIENT_SIGMA, order=(1, 0))

    descs = []

    for x, y in pts:
        if rotation_invariant:
            xi, yi = int(round(x)), int(round(y))
            th = np.arctan2(gy[yi, xi], gx[yi, xi])
            c, s = np.cos(th), np.sin(th)
            X, Y = x + c * U - s * V, y + s * U + c * V
        else:
            X, Y = x + U, y + V
        patch = ndimage.map_coordinates(blurred, [Y, X], order=1, mode="reflect")
        descs.append(((patch - patch.mean()) / (patch.std() + 1e-8)).ravel())

    return np.array(descs)

B.3: Feature Matching

For two neighbouring images, I compute the Euclidean distance between every descriptor of image A and every descriptor of image B (a 500 × 500 matrix with scipy.spatial.distance.cdist). For each feature in A, I find its nearest neighbour (1-NN) and second nearest neighbour (2-NN) in B and accept the match only if $$ \frac{d_{1\text{-}NN}}{d_{2\text{-}NN}} < 0.7. $$ This is the thresholding approach due to Lowe. A distinctive feature has a clearly closer best match than the runner-up (small ratio), whereas for a wrong match (repeated texture, or a feature that has no counterpart in the other image) the best and second-best distances are similar and the ratio is close to 1. As Figure 6b of the paper shows, thresholding this ratio separates correct from incorrect matches much better than thresholding the 1-NN distance alone, because the absolute distance of a correct match varies a lot from feature to feature while the ratio adapts to how distinctive each feature is. I used 0.7, a point on the trade-off between rejecting wrong matches and keeping enough correct ones (a lower threshold gives fewer, cleaner matches; a higher one gives more, noisier matches). Since RANSAC follows, I prefer to keep somewhat more matches rather than too few. In practice about 91–96% of the matches that survive are RANSAC inliers (table in B.4), so this threshold works well here. As instructed, I ignore Section 6 of the paper (fast matching); with only 500 features per image, the exhaustive distance matrix is cheap. 

def match_features(d1, d2, ratio=RATIO_THRESH, cross_check=CROSS_CHECK):
    D = np.sqrt(np.maximum(dist2(d1, d2), 0))
    nn = np.argsort(D, axis=1)[:, :2]
    rows = np.arange(len(d1))
    keep = D[rows, nn[:, 0]] / (D[rows, nn[:, 1]] + 1e-12) < ratio

    if cross_check:
        keep &= np.argmin(D, axis=0)[nn[:, 0]] == rows

    return np.stack([rows[keep], nn[keep, 0]], axis=1)

B.4: RANSAC for a Robust Homography

4-point RANSAC (from scratch)

Least squares (A.2) is badly thrown off by even a few wrong matches, so I use RANSAC. Given the putative matches \(\{(p_i, p_i')\}\) from B.3, I repeat 5000 times:

  1. Pick 4 distinct matches at random, and skip the sample if any 3 of the points in either image are (nearly) collinear, since that does not determine a homography.
  2. Compute the exact homography \(H\) from those 4 matches (the 8×8 system of A.2, solved with the same computeH).
  3. Apply \(H\) to the points of image A and count the matches whose reprojection error \(\lVert Hp_i - p_i' \rVert\) is below \(\varepsilon = 3\) px (the inliers).
  4. Remember the \(H\) with the largest inlier set.

Finally, I re-estimate \(H\) by least squares over all inliers of the best model (the same computeH, now with about 200 correspondences instead of 4) and refit the inlier set once with this \(H\). Parallax and moving objects produce matches that are consistent with no single homography; these are outliers like any other.

Number of iterations. If a fraction \(p\) of the matches are inliers, a random 4-sample is all inliers with probability \(p^4\), so \(N = \log(1 - 0.999)/\log(1 - p^4)\) iterations find a good sample with 99.9% confidence. For \(p = 0.5\) this is about 107 iterations, and for \(p = 0.3\) about 850. My inlier fractions here are above 90%, so 5000 iterations is a very large safety margin, and each iteration is cheap because it only solves an 8×8 system. 

def _collinear_triple(p, tol=1e-3):
    scale = np.ptp(p, axis=0).max() ** 2 + 1e-12
    for a, b, c in ((0, 1, 2), (0, 1, 3), (0, 2, 3), (1, 2, 3)):
        u, v = p[b] - p[a], p[c] - p[a]
        if abs(u[0] * v[1] - u[1] * v[0]) / 2 / scale < tol:
            return True
    return False


def ransac_homography(p1, p2, n_iters=RANSAC_ITERS, eps=RANSAC_EPS, seed=SEED):
    p1, p2 = np.asarray(p1, float), np.asarray(p2, float)
    n = len(p1)

    if n < 4:
        raise ValueError("need at least 4 matches for a homography, got %d" % n)
    rng = np.random.default_rng(seed)
    best, best_count = None, 0

    for _ in range(n_iters):
        idx = rng.choice(n, 4, replace=False)
        if _collinear_triple(p1[idx]) or _collinear_triple(p2[idx]):
            continue
        H = computeH(p1[idx], p2[idx])
        if not np.all(np.isfinite(H)):
            continue
        with np.errstate(all="ignore"):
            err = np.linalg.norm(applyH(H, p1) - p2, axis=1)
        inl = err < eps
        if inl.sum() > best_count:
            best, best_count = inl, int(inl.sum())

    if best is None or best_count < 4:
        raise RuntimeError("RANSAC found no consistent homography")
    H = computeH(p1[best], p2[best])
    inl = np.linalg.norm(applyH(H, p1) - p2, axis=1) < eps

    return (computeH(p1[inl], p2[inl]), inl) if inl.sum() >= 4 else (H, best)

Visual comparison: Visually, both the Manual and Automatic mosaics are indistinguishable from one another. The biggest difference is the amount of evidence behind each homography. The manual mosaics use 8 correspondences per pair, each with a click error of a pixel or two (the mean reprojection errors in A.2 are 0.63 – 1.91 px), and I deliberately chose them on distant, static structure. The automatic mosaics use 156 – 243 correspondences per pair, about 20 to 30 times as many, spread over the whole overlap region and each localized to within the 3 px inlier threshold, and the least-squares fit averages the noise of all of them down. The automatic method also needs no human time, whereas clicking 16 points per image pair is slow and has to be repeated for every new set of photos. The trade-off is that the automatic correspondences are not hand-checked. They are only as good as the detector, the descriptor, and the inlier test, and features on nearby objects that violate the single-plane model are simply discarded by RANSAC as outliers instead of being avoided by a human.

B.5: Bells & Whistles: Rotation Invariance

The base descriptor of B.2 samples its 8×8 grid along the image axes, so if the camera is rolled between two shots, the same scene point has a rotated patch and no longer matches. Following the paper, I make the descriptor rotation invariant by sampling the grid along each corner's own dominant orientation:

  1. Orientation. The gradient of the image blurred at \(\sigma_o = 4.5\) px is evaluated at the corner, and \(\theta = \operatorname{atan2}(g_y, g_x)\). The heavy blur makes the orientation stable under small localization errors.
  2. Rotated sampling. The 8×8 sample offsets \((u, v)\) (spacing 5 px, \(-17.5\) to \(+17.5\)) are rotated by \(\theta\): $$ \begin{bmatrix} x \\ y \end{bmatrix} = \begin{bmatrix} x_0 \\ y_0 \end{bmatrix} + \begin{bmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{bmatrix} \begin{bmatrix} u \\ v \end{bmatrix} $$ and the blurred image is read with bilinear interpolation, followed by the same bias/gain normalization.
  3. Border. The rotated window can reach farther from the corner, so with this option on, corners within 30 px of the border are discarded instead of 20 px.

The code is the rotation_invariant=True branch of extract_descriptors shown in B.2.

Summary of Part B

I detected Harris corners, spread 500 of them evenly over each image with ANMS, describe them with normalized 8 × 8 patches sampled from blurred 40 × 40 windows, match them with the 1-NN/2-NN ratio test, and estimate each homography with my own 4-point RANSAC. This produced three automatic mosaics that I can compare directly with the manual mosaics from Part A. The most useful lessons were that ANMS is a cheap way to avoid leaving regions of an image without features, that the ratio test removes most wrong matches without any knowledge of the geometry, and that RANSAC takes care of the rest, so that 91 – 96% of the remaining matches were consistent with one homography. The most interesting part is that the whole thing runs without a single click, and that adding rotation invariance only required rotating the sampling grid.
