1.1 Convolutions from Scratch

Convolution using Four Loops

def convolution_four_loops (image, kernal) :
    k_flipped = np.flip(kernal)
    k_h, k_w = k_flipped.shape[:2]
    pad_h, pad_w = k_h // 2, k_w // 2

    padded_image = np.pad(image, ((pad_h, pad_h), (pad_w, pad_w)), mode='constant', constant_values=0)
    output = np.zeros_like(image, dtype=np.float64)

    for i in range(image.shape[0]) :
        for j in range(image.shape[1]) :
            acc = 0.0
            for k in range(k_h) :
                for m in range(k_w) :
                    acc += padded_image[i + k, j + m] * k_flipped[k, m]
            output[i, j] = acc

    return output

Convolution using Two Loops

def convolution_two_loops (image, kernal) :
    k_flipped = np.flip(kernal)
    k_h, k_w = k_flipped.shape[:2]
    pad_h, pad_w = k_h // 2, k_w // 2

    padded_image = np.pad(image, ((pad_h, pad_h), (pad_w, pad_w)), mode='constant', constant_values=0)
    output = np.zeros_like(image, dtype=np.float64)

    for i in range(image.shape[0]) :
        for j in range(image.shape[1]) :
            window = padded_image[i: i + k_h, j: j + k_w]
            output[i, j] = np.sum(window * k_flipped)

    return output

I tested my implementation against the built-in convolution function, scipy.signal.convolve2d, and they matched exactly. The only difference was in their runtime:

Implementation Runtime (seconds)
Four Loops9.802
Two Loops1.697
scipy.signal.convolve2d0.053

These runtimes reflect the work that happens. The four loop implementation multiplies one kernel entry at a time, making it almost 6 times slower than the two loop implementation. The two loop version does the multiply and sum of each kernel as a single vectorised NumPy operation. scipy.signal.convolve2d runs on compiled code, allowing it to be about 32 times faster than the two loop implementation and about 185 times than the four loop implementation.

All three versions flips the kernel and uses zero padding, ensuring that the output are the same size as the input and the results agree at the image borders.

Convolving my selfie with the finite difference operator D_x = [1, 0, -1] highlights vertical edges. At each pixel, it takes the pixel on the right minus the pixel on the left, so it responds to the brightness changes along the x-axis.

1.2 Finite Difference Operator

To detect edges in the cameraman image, I convolved the image with the finite difference operators D_x = [1, 0, -1] and D_y = [[1], [0], [-1]]. I then computed the gradient magnitude pixel-wise using the Pythagorean theorem: $$ \sqrt{(I * D_x)^2 + (I * D_y)^2} $$ Finally, I binarized the gradient magnitude image using a threshold of 0.2 to isolate the strongest edges.

To select the best threshold to suppress the noise while showing all the real edges, I swept through various values and compared each one.

From the results above, I decided to select a threshold value of 0.2. At 0.1 and 0.15, many pixels were flagged as edges. This results in a lot of noise in the background. At 0.25 and above, most of the noise have been removed. However, it also starts to drop edges from the cameraman and the tripod. Therefore, 0.2 was the best middle point to ensure that the image while still shows the finer edges of the tripod and the outline of the cameramen.

1.3 Derivative of Gaussian (DoG) Filter

Applying the finite difference operators directly to the original image results in noisy edges. To fix this, I first blurred the image using a Gaussian filter and then applied the difference operators. I also created a derivatibe of Gaussian (DoG) filter by convolving the Gaussian with D_x and D_y first and verified that applying it to the original image returns the same result with only one convolution operation.

Derivative of Gaussian Filters

Since convolution is associative, blurring and then differentiating is the same as convolving the image once with a filter made by combining the Gaussian and the difference operator ahead of time. $$(I * G) * D_x = I * (G * D_x)$$ I built the DoG fikters by convolving the 2D Gaussian kernel directly with d_x and D_y. The resulting filters act as a single operation that smooths the image and extracts the gradient at the same time.

2.1 Image "Sharpening"

I implemented unsharp masking by extracting the high frequencies of an image (Original - Gaussian Blur) and adding them back to the original image. Mathematically, this is expressed as: $$ I_{sharpened} = I + \alpha(I - I * G) $$ where α dictates the sharpening strength.

To determine the best alpha for sharpening, I interated through a series of alphas. The results are display below.

From the comparisons above, we can see that an alpha of 1.0 balances the visually finer edges against oversharpening artifacts, which creates halos around the boundaries, which are more pronounced in higher alpha values.

2.2 Hybrid Images

Hybrid images rely on human visual perception. We see high frequencies up close and low frequencies from afar. I created hybrid images by blending the high frequencies of one image (via a Laplacian-style subtraction) with the low frequencies of another (via a Gaussian blur).

Derek and Nutmeg

Hybrid images work by combining frequency content that is spatially registered. Therefore, it is important to align the facial features of Derek and Nutmeg. For this, I aligned both images by selecting both eyes of Derek and Nutmeg. The code then rescales, rotates, and centers both images based on the selected points.


Cutoff Frequencies

To find out the best cutoff frequencies, I swept through various values for sigma (σ). σ1 is the low pass cutoff applied to Derek (image1). A larger σ1 blurs him more, so only coarser structures survives. σ2 is the cutoff used to build the high pass version of Nutmeg (image2). It is computed as the original image of Nutmeg minus a blurred Nutmeg. A larger σ2 removes on the lowest frequencies, so more of its details are passed through.

A small σ1 leave too much of Derek's fine features that competes with Nutmeg's details up close, while having too large of a σ1 turns him into a shapeless blur that is hard to recognise at far distances. A small σ2 leaves too little of Nutmeg to see up close, while a large σ2 lets too much of its structure thorugh that she dominates the image even at a far distance. For Derek and Nutmeg, I chose σ1 = 12 and σ2 = 8 as the it gave the best balance between the two. For the two other examples, I followed this same procedure, but will not be showing this grid.

2.3 Gaussian and Laplacian Stacks

Rather than downsampling, I kept every level at full resolution and built each successive Gaussian stack level by reapplying the same sigma = 8 Gaussian filter to the previous level so that the blur is accumulated across the stack. This produced a stack that behaves similarly to a downsampled pyramid without the resolution loss.

The Most Important Thing I Learnt

The most important thing I learnt is that images are not just static grids of pixels, but consist of high and low frequencies that can be used to manipulate human perception.

By isolating these high and low frequencies using Gaussian filters and Laplacian substraction, I saw how high frequencies dictate sharp edges and fine details, while low frequencies controls smooth colour gradients and overall image structure. This dual nature is what helped me make hybrid images like "Lord Squaadward" and "Tankbob" possible. By mathematically overlaying the high frequency details of one subject onto the low frequency base of the other, the resulting image is able to trick the human eye purely based on the viewing distance.
